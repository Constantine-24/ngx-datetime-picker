# ngx-datetime-picker v1.0.0

The first public release of **ngx-datetime-picker** — a configurable Angular
date & time picker built on `@angular/cdk` and `@angular/material` primitives.
One cohesive API presents **five variants**, works with **any `DateAdapter`**,
and ships a **TC39 Temporal** adapter as the flagship default.

## Highlights

- **Five variants, one component.** `<ngx-dt-picker [type]>` covers `date`,
  `date-range`, `time`, `datetime`, and `datetime-range`, in overlay (default)
  or inline mode.
- **Temporal-first, adapter-agnostic.** Built on Material's `DateAdapter<D>`, so
  it works with native `Date`, Luxon, or date-fns — and ships a first-class
  `Temporal.PlainDate` / `PlainTime` / `PlainDateTime` adapter in a secondary
  entry point. The polyfill tree-shakes away if you don't use it.
- **Forms, every way.** Each input is a `ControlValueAccessor` _and_ a validator,
  so Reactive Forms, `ngModel`, and Signal Forms (`[formField]`) all just work,
  with descriptive error keys (`ngxDtParse`, `ngxDtMin`, `ngxDtMax`,
  `ngxDtFilter`, and range variants).
- **A real time picker.** A custom stepper panel with 12/24-hour display,
  configurable minute step, optional seconds, and complete spinbutton keyboard
  support (Arrow/Home/End/Page keys + type-to-set) with live announcements.
- **Range done right.** Dual synced calendars (`monthsToDisplay="2"`), datetime
  ranges with independent start/end time panels, and same-day clamping.
- **Draft mode.** `draftMode` buffers edits in the overlay until **Apply** —
  **Cancel**, Escape, or a backdrop click reverts.
- **Accessible by default.** `role="dialog"` + `aria-modal`, CDK focus trap,
  focus restoration, WCAG AA contrast, and AXE-clean output.
- **Themes itself.** Consumes `--mat-sys-*` tokens to match your `mat.theme()`
  automatically, honors `prefers-reduced-motion`, and supports RTL.

## Installation

```bash
npm install @constantine-24/ngx-datetime-picker @angular/material @angular/cdk temporal-polyfill
```

`temporal-polyfill` is required by the `/temporal` entry point (the Temporal
adapters import it). It is an optional peer only for apps that use the core with
their own adapter.

Provide the adapter that matches your variant in `app.config.ts`:

```ts
import { provideTemporalDateAdapter } from '@constantine-24/ngx-datetime-picker/temporal';

export const appConfig: ApplicationConfig = {
  providers: [provideTemporalDateAdapter()],
};
```

| Variant(s)                   | Provider                           |
| ---------------------------- | ---------------------------------- |
| `date`, `date-range`         | `provideTemporalDateAdapter()`     |
| `time`                       | `provideTemporalTimeAdapter()`     |
| `datetime`, `datetime-range` | `provideTemporalDateTimeAdapter()` |

## Quick start

```html
<mat-form-field>
  <mat-label>Pick a date</mat-label>
  <input matInput [ngxDtInput]="picker" [formControl]="dateCtrl" />
  <ngx-dt-toggle matSuffix [for]="picker" />
</mat-form-field>
<ngx-dt-picker #picker="ngxDtPicker" />
```

See the [README](../../projects/ngx-datetime-picker/README.md) for every variant,
the full input/output reference, validation error keys, theming, and RTL.

## Known limitations

- **Dual-calendar keyboard navigation** (`monthsToDisplay="2"`): each calendar
  keeps its own month state, so arrow-key navigation past a month edge moves
  only that calendar — use the shared prev/next header buttons to move both.
  This is a structural constraint of the underlying `MatCalendar`.
